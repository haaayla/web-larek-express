# Web-ларёк

Учебный проект: интернет-магазин «Web-ларёк». Фронтенд на React с админкой (папка `frontend`) и бэкенд на Express + TypeScript + MongoDB (папка `backend`). Проект состоит в реализации бэкенда: каталог, заказы, авторизация, загрузка изображений и управление товарами.

## Что в репозитории

| Папка | Назначение |
|---|---|
| `backend/` | Сервер на Express + TypeScript |
| `frontend/` | Фронтенд на React с админкой, нужен для проверки бэкенда |

## Технологии бэкенда

- TypeScript, Node.js и Express
- MongoDB и ODM Mongoose
- `celebrate` + `joi` — валидация входящих запросов
- `jsonwebtoken` — JWT-токены, `bcryptjs` — хеширование паролей, `cookie-parser` — чтение кук
- `multer` — приём загружаемых файлов
- `validator` — проверка email в схеме пользователя
- `winston` + `express-winston` — логирование запросов и ошибок
- `@faker-js/faker` — генерация идентификатора заказа
- ESLint (Airbnb) — стиль кода

## Требования

- Node.js 22 (подходят также 20.19+ и 24+)
- npm
- MongoDB (проверено на версии 9.0; адрес по умолчанию `mongodb://127.0.0.1:27017`)

## Быстрый старт

**1. Запустите MongoDB.** Например, на macOS через Homebrew:

```bash
brew tap mongodb/brew
brew install mongodb-community
brew services run mongodb-community
```

**2. Запустите бэкенд.** В новой вкладке терминала:

```bash
cd backend
npm ci
cp .env.example .env
npm run dev
```

Сервер стартует на порту из `.env` (по умолчанию `3000`) и подключается к базе по `DB_ADDRESS`.

**3. Запустите фронтенд.** В ещё одной вкладке терминала:

```bash
cd frontend
npm ci
cp .env.example .env
npm run dev
```

Откройте <http://localhost:5173>. В `frontend/.env` переменная `VITE_API_ORIGIN` должна указывать на бэкенд (`http://localhost:3000`).

**4. Добавьте товары.** База изначально пустая. Зарегистрируйтесь на странице `/register`, затем откройте `/admin`: можно создавать, редактировать и удалять товары и загружать для них изображения.

## Переменные окружения бэкенда

Файл `backend/.env` создаётся копированием `backend/.env.example` и в git не попадает. Все параметры приложения берутся только оттуда; если переменная не задана или срок записан неверно, сервер не запустится.

| Переменная | Назначение |
|---|---|
| `PORT` | Порт сервера |
| `DB_ADDRESS` | Адрес базы MongoDB (имя переменной менять нельзя) |
| `ORIGIN_ALLOW` | Адрес фронтенда, которому разрешены запросы с куками (CORS) |
| `UPLOAD_PATH` | Папка постоянного хранения изображений внутри `src/public` (`images`) |
| `UPLOAD_PATH_TEMP` | Временная папка загрузок внутри `src` (`temp`) |
| `AUTH_ACCESS_TOKEN_EXPIRY` | Срок жизни access-токена, например `10m` |
| `AUTH_REFRESH_TOKEN_EXPIRY` | Срок жизни refresh-токена, например `7d` |
| `AUTH_ACCESS_TOKEN_SECRET`, `AUTH_REFRESH_TOKEN_SECRET` | Секреты подписи токенов (в `.env.example` стоят учебные значения, в реальном проекте их нужно заменить на случайные) |

## API

| Метод и адрес | Описание | Доступ | Успех | Ошибки |
|---|---|---|---|---|
| `GET /product` | Список товаров: `{ items, total }` | открыт | 200 | 500 |
| `POST /product` | Создание товара | токен | 201 | 400, 401, 409, 500 |
| `PATCH /product/:productId` | Обновление товара (все поля необязательные) | токен | 200 | 400, 401, 404, 409, 500 |
| `DELETE /product/:productId` | Удаление товара, в ответе удалённый товар | токен | 200 | 400, 401, 404, 500 |
| `POST /order` | Оформление заказа: `{ id, total }` | открыт | 200 | 400, 500 |
| `POST /upload` | Загрузка изображения (поле формы `file`) | токен | 200 | 400, 401, 500 |
| `POST /auth/register` | Регистрация | открыт | 201 | 400, 409, 500 |
| `POST /auth/login` | Вход | открыт | 200 | 400, 401, 500 |
| `GET /auth/token` | Новая пара токенов по refresh-токену из куки | кука | 200 | 401, 404, 500 |
| `GET /auth/logout` | Выход: refresh-токен удаляется из базы | кука | 200 | 400, 401, 404, 500 |
| `GET /auth/user` | Текущий пользователь | токен | 200 | 401, 404, 500 |
| любой другой адрес | — | — | — | 404 |

Ошибки возвращаются в формате `{ "message": "..." }`. Ошибки валидации, перехваченные `celebrate`, имеют его собственный формат (`statusCode`, `error`, `message`, `validation`).

### Авторизация

- При регистрации и входе сервер возвращает `{ user: { email, name }, success: true, accessToken }` и устанавливает httpOnly-куку `refreshToken`.
- Защищённые маршруты принимают access-токен в заголовке `Authorization: Bearer <токен>`. Без него или с просроченным токеном ответ 401.
- Access-токен живёт 10 минут, refresh-токен 7 дней. При обновлении (`GET /auth/token`) старый refresh-токен перестаёт действовать, при выходе он удаляется из базы.
- Пароли хранятся только в виде хеша, в ответах пароль и токены не возвращаются.

### Товар и загрузка изображений

**Товар** (`POST /product`):

```json
{
  "title": "Мамка-таймер",
  "image": { "fileName": "/images/Asterisk_2.png", "originalName": "Asterisk_2.png" },
  "category": "софт-скил",
  "description": "Будет стоять над душой и не давать прокрастинировать.",
  "price": null
}
```

`title` — от 2 до 30 символов, уникальный. `description` и `price` необязательные, `price` по умолчанию `null` (товар не продаётся).

**Загрузка** (`POST /upload`): допустимы `image/png`, `image/jpg`, `image/jpeg`, `image/gif`, `image/svg+xml` размером до 5 МБ. Файл сохраняется во временную папку под уникальным именем, в ответе приходит `{ "fileName": "/images/<имя>.png", "originalName": "..." }`. Этот объект передаётся в поле `image` при создании или обновлении товара: тогда файл переносится в `public/images` и становится доступен по адресу `/images/<имя>`. При удалении товара его файл удаляется, если им не пользуется другой товар.

**Заказ** (`POST /order`):

```json
{
  "payment": "card",
  "email": "admin@ya.ru",
  "phone": "+79999999999",
  "address": "Санкт-Петербург, Восстания 1",
  "total": 2200,
  "items": ["<_id товара>", "<_id товара>"]
}
```

`payment` — `card` или `online`. Все товары из `items` должны существовать и продаваться (`price` не `null`), а их суммарная цена — совпадать с `total`, иначе ответ 400.

## Структура `backend/src`

| Путь | Назначение |
|---|---|
| `app.ts` | Точка входа: настройка Express, подключение к базе, запуск сервера |
| `config.ts` | Чтение параметров из `.env` |
| `constants.ts` | Общие константы (границы длин, размер и типы файлов) |
| `models/` | Схемы и модели товара и пользователя |
| `controllers/` | Логика обработки запросов (товары, заказ, авторизация, загрузка) |
| `routes/` | Адреса и привязка к контроллерам |
| `middlewares/` | Проверка токена, валидация запросов, приём файлов, логгеры, централизованный обработчик ошибок |
| `errors/` | Классы ошибок: 400, 401, 404, 409 |
| `utils/` | Работа с токенами и файлами |
| `public/` | Раздаваемые клиентам файлы (картинки товаров в `public/images`) |

## Логи

В папке, откуда запущен сервер (при запуске через `npm` это `backend`), создаются файлы в формате JSON: `request.log` (все запросы к API) и `error.log` (все ошибки, в том числе ошибка подключения к базе). Заголовки `authorization` и `cookie` в логи не попадают. В git файлы логов не добавляются.
